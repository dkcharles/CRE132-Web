# Welcome

This site is where you will write and run C# for CRE132. There is nothing to install and
nothing to configure — the code you write runs right here, inside this page, in your browser.
Nothing you type is sent anywhere.

Your work is saved automatically as you go, but only in *this browser, on this device*. It is
not backed up to an account and it will not follow you to another computer — so if you switch
machines partway through, or clear your browser's data, what you typed here will not come
with you.

## The course in four parts

The lessons run in order, and they fall into four parts.

**Part 1 · Foundations** — Lessons 0 to 12 — is console programs: text in, text out. This is
where you learn what a program is, how to keep and change values, how to make decisions and
repeat work, and how to break a program into pieces you can name and reuse.

**Part 2 · Graphics & motion** — Lessons 13 to 19 — leaves the text console for a canvas. You
draw shapes, move them frame by frame, read the keyboard, and finish the part by building
Pong.

**Part 3 · Objects & real games** — Lessons 20 to 25 — is about classes: describing a kind of
thing once, then making as many of them as your game needs. It ends with Snake.

**Part 4 · Going further** — Lesson 26 — is not more material to get through. It is a set of
things to study and try out once you have enough C# to read other people's programs and
change them.

## How the module runs

Weeks 1 to 3 cover Part 1, Weeks 4 and 5 cover Part 2, and Weeks 6 and 7 cover Part 3. The
labs follow the lessons in order, one or two lessons a week, so the surest way to keep up is
to work through this site in the order it is written — doing the challenges rather than
reading past them.

Here is what a running program looks like on this site:

:::run s00-hello A friendly hello from the site itself.

Press **Run this** and watch the three lines appear below the code. That is the whole loop
you will use for the rest of the course: read a little, run some code, see what happens.

:::key
You learn to code by running code and changing it — not by reading about it. Every lesson
here gives you real code to press Run on, and real code to edit.
:::

## Read, Run, edit, Check

Every lesson on this site follows the same shape:

- **Read** a short explanation with a code example.
- **Run** the example to see it work for yourself.
- **Edit** an example yourself and run your own version.
- **Check** a small challenge against the exact output it expects.

Try the edit step now. The box below already has some code in it — change the message inside
the quotes to something of your own, keep the quotes, and press Run:

:::edit s00a-your-name

:::try
Made it print your own message? Try pressing **Reset** to bring back the original, then edit
it again a different way. There is no wrong way to experiment here — every attempt just runs
and shows you what happened.
:::

## Challenge

:::challenge c00-first-change

```

```

Change the message so it prints **exactly** this instead:

```
I can run C# programs in my browser.
```

Then press **Check** — your output has to match exactly.
:::

## The keyboard, once games arrive

From Part 2 onwards, some of the programs listen to the keyboard. Click the canvas — or just
somewhere on the page — before you press anything, so the keys reach the game and not the
browser. While a game is playing, the arrow keys and Space belong to the game, and **Escape**
stops it. If you switch to another tab the game pauses and shows a message on the canvas
until you come back, so nothing carries on running while you are not watching.

## When you are stuck

Sooner or later something will refuse to run, or will run and do the wrong thing. Read the
error message from the top: it names a line and the thing it could not make sense of. The
computer is being precise, not unkind.

:::key
An error message is help, not punishment. Read it from the top and fix the first thing it
names — most errors are one missing quote, bracket or semicolon.
:::

If an edit has got away from you, press **Reset**; the original code comes back and you can
try the change again. If a challenge will not pass, do the smaller thing first — print the
value you are unsure about, or get one line of the expected output right before worrying
about the rest. After a Check that does not pass, the page offers you a **hint**; after three
tries that did not pass, it offers the **solution**, which you can copy into the editor. Use
the hint before the solution, and when you do look at the solution, read it against your own
attempt — the difference is the lesson.

You can and should ask for help from your peers and the teaching staff, though the struggle
of problem solving on your own is how you learn most.

## After this site

What this site teaches you is C#, and the C# is the part that lasts. Later modules move you
to Visual Studio on a desktop machine, and to Unity for making games — bigger tools, with a
lot more built around your code. The `if`s, the loops, the methods and the classes you learn
here carry over to both of them unchanged; what changes is where you type them and how much
they can reach.

That's the whole site: read, run, edit, check. The next lesson starts explaining how the code
itself actually works — press **Next** when you're ready.
